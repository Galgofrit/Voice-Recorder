This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Fossify Voice Recorder is an open-source Android voice recording app (`org.fossify.voicerecorder`). Single-module Gradle project (`:app`) written in Kotlin with View Binding (no Jetpack Compose in app code; Compose only appears via the detekt lint rules). It builds on the shared `org.fossify:commons` library, which provides base activities, theming, dialogs, and storage/SAF helpers — much app behavior is inherited from there.

## Build & Tooling Commands

There is no `core` source set despite a `core` flavor being registered; use `foss` or `gplay` for local builds.

```bash
# Build a debug APK (pick a flavor: Foss or Gplay)
./gradlew assembleFossDebug

# Install on a connected device/emulator
./gradlew installFossDebug

# Static analysis — both must pass for CI
./gradlew detekt          # Detekt (config in detekt.yml, baseline app/detekt-baseline.xml)
./gradlew lintFossRelease  # Android Lint (config lint.xml, baseline app/lint-baseline.xml)

# Full release build
./gradlew assembleGplayRelease
```

- **No unit/instrumented tests exist** in this repo; there is no test source set. PRs are validated by build + detekt + lint only.
- Detekt runs with `maxIssues: 0` and `abortOnError = true` for lint — treat both as hard gates. Existing violations are suppressed via baselines, regenerated by CI (`update-lint-baselines.yml`); do not hand-edit baselines.
- Versioning lives in `gradle.properties` (`VERSION_NAME`, `VERSION_CODE`, `APP_ID`). Dependency versions are centralized in `gradle/libs.versions.toml`.
- Min SDK 26, target/compile SDK 36, Java/JVM 17.

## Product Flavors

`flavorDimensions = ["variants"]` with `foss` and `gplay` (and an unused `core`). The only difference is `res/values/bools.xml` toggles consumed by commons: `hide_google_relations`, `show_donate_in_about`, `pretend_thank_you_installed`. Keep flavor-specific divergence limited to resources; app Kotlin code is shared.

## Architecture

**Recording pipeline (the core of the app):**

- `RecorderService` (foreground service in `services/`) owns the entire recording lifecycle. It is driven by `Intent` actions defined in `helpers/Constants.kt` (`GET_RECORDER_INFO`, `TOGGLE_PAUSE`, `CANCEL_RECORDING`, `STOP_AMPLITUDE_UPDATE`; a null/other action starts recording). It manages duration/amplitude `Timer`s, the foreground notification, and writes output to either a `File` path or a SAF `ParcelFileDescriptor` (SD card / scoped storage on R+).
- `recorder/Recorder` is the abstraction implemented by two backends, chosen by the configured `EXTENSION`:
  - `MediaRecorderWrapper` — wraps Android `MediaRecorder` for M4A (AAC) and OGG (Opus).
  - `Mp3Recorder` — raw `AudioRecord` PCM capture encoded to MP3 via the TAndroidLame library, on a background thread with `AtomicBoolean`/`AtomicInteger` for cross-thread pause/amplitude state.
- Audio settings (extension, bitrate, sampling rate, microphone mode) come from `Config`. `Constants.kt` holds the valid bitrate/sampling-rate tables and the per-codec `SAMPLING_RATE_BITRATE_LIMITS` used to constrain UI choices.

**Communication — GreenRobot EventBus:** The service does not bind. It broadcasts state to the UI via `EventBus` using the event classes in `models/Events.kt` (`RecordingDuration`, `RecordingStatus`, `RecordingAmplitude`, `RecordingCompleted`, `RecordingSaved`, `RecordingTrashUpdated`). Fragments/activities subscribe with `@Subscribe`. When changing recorder behavior, keep the event contract in sync on both ends.

**UI structure:** Single-Activity-ish with `SplashActivity` → `MainActivity` hosting a `ViewPager` (`ViewPagerAdapter`) of three `MyViewPagerFragment` subclasses: `RecorderFragment`, `PlayerFragment`, `TrashFragment`. All activities extend `SimpleActivity` (→ commons `BaseSimpleActivity`). Recordings list/trash use `RecordingsAdapter`/`TrashAdapter`.

**Storage & models:** `models/Recording.kt` represents a recording. Files are stored under `Config.saveRecordingsFolder` (default `Recordings`). The recycle-bin ("trash") feature is gated by `USE_RECYCLE_BIN`. SAF/DocumentFile handling for SD-card and Android R+ scoped storage is concentrated in `extensions/DocumentFile.kt`, `extensions/Context.kt`, and commons helpers — prefer those over raw `File` APIs when writing to user-selected trees.

**Config & extensions:** `helpers/Config.kt` (extends commons `BaseConfig`) is the single source of truth for persisted prefs; keys are the string constants in `Constants.kt`. `Context.config` / `Activity` extensions in `extensions/` are the idiomatic entry points. Filenames are generated from a user `FILENAME_PATTERN` (default `%Y%M%D_%h%m%s`) via `extensions/getFormattedFilename`.

**Home-screen widget:** `MyWidgetRecordDisplayProvider` + `WidgetRecordDisplayConfigureActivity` provide a one-tap record widget that talks to `RecorderService`.

## Conventions

- Kotlin sources live under `app/src/main/kotlin` (not `java`); the `main` source set is remapped accordingly in `build.gradle.kts`.
- `nonTransitiveRClass` is on — reference `R` from the app's own package, and commons resources via the commons `R`.
- Magic numbers are flagged by detekt; either name a constant or annotate. Max line length is 120.
- Release builds are minified + resource-shrunk (R8); update `app/proguard-rules.pro` when adding reflection-based or library code that gets stripped.
